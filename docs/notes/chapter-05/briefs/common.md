# What every brief for Chapters 5 and 6 shares

Write for a Jupyter notebook read by a data engineer; the reader is "you". Follow `docs/style.md`
and `AGENTS.md`: British English, short plain sentences, no em dashes, no filler, no reassurance,
no narration of what the chapter does or will do, nothing that personifies a system, a record, a
cell, a check, a graph or a model. Keep every name in backticks exactly as written. A block of code
is a "cell". The buttons are **Run all**, **Run below** and **Save**, in bold; name no other
control. Never refer to Jo Marsh or Sam Lund as "he" or "she": repeat the name.

Words the chapters already use, with one meaning each: *records* is a whole set of lines, one of
them a *line*; *entity*, *attribute*, *identifier* and *dataset* as Chapter 4 defined them (an
entity is a thing the records describe, with a type; an attribute a named property of a type; an
identifier the value that names one entity of its type in every line; a dataset a file or a table
of rows); *asset* (a file, a table or the dashboard); *job* (what runs each night).

The reader has been told to press **Run all** first, so when they reach a cell for their
expectation, the cells below it have already run: ask them to write it "before you read on".

Write the file once. Do not change it after you reply.
