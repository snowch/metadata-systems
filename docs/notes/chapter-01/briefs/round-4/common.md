# Instructions for every Chapter 1 brief in the fourth round

You are redrafting learner-facing text for an interactive course, *Metadata Systems*, after the
author's fourth round of feedback. Read these first, in full:

- `docs/notes/chapter-01/facts.md`: the only facts you may use. Every number, name and time you
  write must be in it. Do not invent a number, a name, a time or a behaviour.
- `docs/style.md`: the style checklist. Apply both passes.
- `docs/notes/chapter-01/briefs/round-3/common.md`, and the files it names: every rule there still
  holds.

What this round changes, so that your text serves it:

- **A prediction asks for a result, not an explanation.** Each option names a result the learner
  could expect and the belief it reflects, in a few words. No option, question or caption says or
  hints why the result will be what it is: the explanation comes after the evidence.
- **The effect before its cause.** Until the lab shows a difference, nothing says there is one.
  Once it does, the text asks what might explain it and leaves the answer to the investigation.
- **"I can't tell yet" is a fair answer** where nothing seen so far settles the question. Nothing
  calls it wrong.

Each key below says where the text appears and lists the facts it must carry. The facts are a
list, not wording: write your own sentences. Keep every `{slot}` exactly as written, braces
included, and add no other slot. Where a key says plain text, write no Markdown and no backticks.
Where a key says names in backticks, put each name of an asset or a file between backticks, as in
`daily_sales`.

Write your draft to the file your brief names, as Markdown with one `## key` heading per item, in
the brief's order, and nothing else under each heading but the text itself. For a key that takes
several labels, write them as a Markdown list with the label's key before a colon
(`same: ...`), in the brief's order.
