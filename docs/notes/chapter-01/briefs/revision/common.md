# Instructions for every Chapter 1 revision brief

You are redrafting learner-facing text for an interactive course, *Metadata Systems*, after an
outside review. Read these first, in full:

- `docs/notes/chapter-01/facts.md`: the only facts you may use. Every number, name and time you
  write must be in it. Do not invent a number, a name, a time or a behaviour.
- `docs/style.md`: the style checklist. Apply both passes.
- `docs/notes/chapter-01/briefs/common.md`: the rules every Chapter 1 brief follows. They all
  still hold.

What the review found, so that you do not repeat it:

- Long sentences built as a colon followed by a list of clauses. Write one idea per sentence. Put
  a list of things in a Markdown list.
- The same conclusion said in several places. Say only what your brief asks for, where it asks.
- A word used in two senses. Use the fact sheet's "Words on this page" exactly: "rebuild",
  "storage", "platform", "responsible", "the last night's write", "an order that appears twice".
- Text shown before the learner commits to a prediction that hints at the answer. Where a key
  says "shown before the learner commits", it must not say or hint what the lab will find.
- Groups named by position ("the middle column"). Name a group by its heading.
- Claims that a system "must" or "needs to" keep something. Say what the lab keeps.

Each key below says where the text appears and lists the facts it must carry. The facts are a
list, not wording: write your own sentences. Keep every `{slot}` exactly as written, braces
included, and add no other slot. Captions, option labels, button labels and headings are plain
text: no Markdown, and no full stop unless the key says so.

Write your draft to the file your brief names, as Markdown with one `## key` heading per item, in
the brief's order, and nothing else under each heading but the text itself. For a key that takes a
list of items (objectives, hints), write the items as a Markdown list.
