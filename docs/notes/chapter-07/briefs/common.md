# What every brief for Chapters 7, 8 and 9 shares

Write for a Jupyter notebook read by a data engineer; the reader is "you". Follow `docs/style.md`
and `AGENTS.md`: British English, short plain sentences, active voice, no em dashes, no filler, no
reassurance, no narration of what the chapter does or will do, no "in this chapter", nothing that
personifies a system, a program, an event, a cell, a check or a graph. Say the thing; do not build up
to it. Keep every name in backticks exactly as written. A block of code is a "cell". The buttons are
**Run all**, **Run below** and **Save**, in bold; name no other control. Never refer to Jo Marsh or
any person as "he" or "she": repeat the name.

Words the chapters already use, with one meaning each: *records* is a whole set of lines, one of them
a *line*; *entity*, *attribute*, *identifier*, *dataset* (a file or a table of rows); *asset* (a file,
a table or the dashboard); *job* (one of the four programs that run each night); *node*, *edge*,
*graph*, *traversal*; *lineage* (records of what was made from what, and by which job), *upstream*,
*downstream*. Never "walk": say "traversal" or "follows edges".

The nights: each night's work runs in the early hours of the next day, so the work that read
Thursday's orders ran early on Friday 11 September. Name a night's work by the date it ran on: "the
run on Friday 11", and say once that it read the orders up to Thursday.

The reader has been told to press **Run all** first, so when they reach a cell for their expectation,
the cells below it have already run: ask them to write it "before you read on".

Never write: lab, engine, simulator, Jupyter, notebook (say "page" if needed), impact analysis,
provenance, root cause, identity, observation, freshness, column lineage.

Write the file once. Do not change it after you reply.
